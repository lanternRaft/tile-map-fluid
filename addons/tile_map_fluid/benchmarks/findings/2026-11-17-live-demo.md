# Live demo performance on Apple M1 Pro

A 64×64-pixel obstacle edit on the 128×128 floor now takes **0.54 ms**, down from
**5.32 ms**. Steady one-hose throughput stayed around **0.87 ms per tick**. Reaching
twice that steady throughput calls for changes to both spray processing and receiver
updates. Four simultaneous hoses shift most of the cost into spray processing.

## Local obstacle edits

The probe alternated a real door collider open and closed 20 times after each
seeded live route. It verified that a floor contact at the center disappeared
and returned on each transition. Each timing covers synchronous clipping, storage
and notifications. The subsequent render refresh falls outside this interval.

| Median of three trials | Whole-field lookup rebuild | Persistent lookup by corner position |
| --- | ---: | ---: |
| Regional refresh p50 | 5.318 ms | 0.544 ms |
| Regional refresh p95 | 6.033 ms | 0.618 ms |
| Whole live loop before edits | 0.859 ms/tick | 0.861 ms/tick |
| Synchronous demo setup | 273 ms | 294 ms |
| Engine static allocation after live route | 74.63 MiB | 77.67 MiB |

Replacing a few cells previously rebuilt a dictionary from every surviving
sample. The new index looks up slots only at touched corner positions. A seam
can have multiple slots with different water levels. Reconnection checks their
current, passively dried values and preserves the original slot tie break.
All six runs produced identical saturation-buffer hashes before the door probe
and identical hashes after it. The measured **9.8×** reduction in edit time costs
about **3.0 MiB** of additional engine static allocation on this map and **21 ms** of setup.
A separate refresh of unchanged geometry measured 4.895 → 0.429 ms.

## Steady live workload

Times below are median wall-clock microseconds per fixed physics tick over three
fresh processes. Every run kept the moving player, floor, props, barriers,
receiver query proxies, visuals and presentation in the scene.

| One-hose case | µs/tick | Range of trial means |
| --- | ---: | ---: |
| Full workload | 874 | 873–882 |
| Hose emission disabled | 515 | 511–519 |
| Receiver physics updates disabled | 596 | 590–597 |
| Both disabled | 250 | 248–251 |

**For four hoses, prioritize the spray kernel.** Full throughput cost
**1,998 µs/tick** (1,983–2,003), falling to **521 µs/tick** (514–521) with emission
disabled. Holding that remainder fixed, making the spray-associated work more
than **3.1× faster** would bring the complete four-hose case below 999 µs/tick.

The two one-hose spray-on cases produced the same final floor hash and 3,600 emissions
per trial. Disabling a subsystem can also remove downstream work, including wet
texture uploads or tint changes. Treat the deltas as estimates of the available
time budget.

**For one hose, prototype a surface-owned receiver activity index alongside an
ordered spray kernel.** More than 2× means fewer than **437 µs/tick** for the whole
loop. With the 250 µs remainder held fixed, the combined spray and receiver work
must fall from about **625 to under 187 µs/tick**, a reduction by a factor greater
than **3.33**. Eliminating either subsystem alone fell short.

- For receivers, index stationary contacts by their supporting sample slots.
  Wake them on writes to those slots, movement, contact/settings changes and
  geometry replacement. Keep wet, absorbing, moving and dynamically bound objects
  on the reference update path. A diagnostic run found **166,772 of 241,200**
  receiver ticks had unchanged position, dry floor and zero object water (69%).
  This is a candidate population. Some still need live contact or traction work.
- For spray, prototype a single native call per hose tick with packed regular-cell
  data, local candidate colliders and reusable scratch storage. Keep ordered
  per-splash read, radius calculation and write, including synchronous signal
  boundaries and the exact visibility fallback for underpaint and clipped cells.
  The one-hose run issued **223,159 floor-corner physics rays** for **16,305 splashes**.
  Only **1,270** splashes (7.8%) had a blocker-free bounding box covering every
  visited cell on this populated route. A whole-box empty check alone has limited
  reach here.

Use fixed-tick reference replays for dose order, immediate reads, receiver
signals, wall visibility and final field state. Judge the prototype by the full
live loop and rendered tails. The disabled-work cases measure headroom only.

## Rendered target

Three 30-wall-second trials per speed used a 960×640 drawable Compatibility
window, VSync off and uncapped rendering. Each table entry is the median of the
three trial statistics.

| Live speed | FPS | Achieved / required ticks per second | Frame p95 | Frame p99 | Frames over 8.33 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1× | 519 | 120 / 120 | 3.41 ms | 4.47 ms | 0.025% |
| 8× | 20.4 | 914 / 960 | 78.24 ms | 82.71 ms | 100% |

All three 8× trials missed the 120 FPS target. Headless throughput compares
implementations at identical tick counts. Rendered trials include graphics and
wall-clock scheduling, and cover more simulated route time at 8×.

## Reproduction

Godot 4.7.2 stable `ed1daf0bf`, Apple M1 Pro, macOS 26.3 (25D125), stock
physics. Fixed trials used seed 13463, 240 warmup ticks, 3,600 measured ticks
at 1/120 s, 64 workload receivers plus three original props/character, eight
barriers, 32 px field spacing and 72-second floor drying. The demo previously
emitted twice per hose tick and duplicated runtime query proxies when cloning
mushrooms. One configured hose now emits once and 67 receivers own 67 proxies.
Earlier live-demo timings used a different workload.

```sh
python3 tools/bench_demo.py --cases live no-spray no-contact-ticks neither
python3 tools/bench_demo.py --hoses 4 --cases live no-spray
python3 tools/bench_demo.py --edit-probe
python3 tools/bench_demo.py --mode rendered --speed 1
python3 tools/bench_demo.py --mode rendered --speed 8
```

For the door A/B, use two copies of the revised demo and runner. In the reference
copy, use `addons/tile_map_fluid/wet_field_storage.gd` from commit `fd7cf7b`.
The three pairs ran sequentially in scan/indexed, indexed/scan, scan/indexed
order. The local raw reports are in `reports/benchmarks/live-demo/` under
`door-{1,2,3}-{scan,indexed}/`, `final/`, `final-four-hoses/`, and `rendered-*/`.
`operation-counts/` includes the separate instrumentation patch and raw counts.
Timing tables use uninstrumented production components. All results describe this
demo and machine. Game integration and low-end hardware performance remain open.
