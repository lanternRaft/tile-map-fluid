## Protocol and commands

The runner instantiates the actual demo, then calls its existing live-stress
setup: 128×128 tiles, 64 workload receivers, eight workload barriers, one live
cone hose, the character and both original props, 72-second floor drying.
Seed 13463; warmup 240 simulation ticks; fixed trials measure 3,600 ticks
(30 simulated seconds) with delta 1/120. The moving case additionally moves
all 64 workload bodies along the same small, deterministic trajectory every
tick. It does not replace the hose or remove other demo objects.

Before implementation changes, three repeated baseline trials measured
wettable updates at 1.178–1.186 ms/tick and aggregate scopes at
1.920–1.929 ms/tick with the initial diagnostic instrumentation. The
predeclared improvement gate was **5% in both wettable and aggregate addon
CPU**, comfortably above the observed <1% spread. Diagnostic instrumentation
was subsequently separated from lighter acceptance instrumentation; only
identically instrumented source variants are compared. No diagnostic timing
is treated as uninstrumented cost.

`stage1_trials.py` runs three matched pairs in B/C, C/B, B/C order for
stationary and moving CPU cases, then for 1× and 8× rendered cases. Each
rendered trial measures at least 30 wall-clock seconds. `stage1_extra.py`
collects finer diagnostic scopes, startup/regional/full-edit costs, two-hose
exact per-tick replays, three uninstrumented CPU pairs per movement case,
sustained uninstrumented 225-second 1× / 90-second 8× confirmations. These are sequential, with no concurrent
benchmarks. Setup and warmup are excluded from steady timing. OS child CPU
includes setup/warmup and is labeled separately.

## Implementation and correctness

Each receiver retains one geometry-only handle: supporting surface and grid,
coverage and geometry revisions, world point and layer transform, first
containing patch identity, four sample indices, and bilinear fractions.
Changed points are prepared again, including polygon boundaries and negative
coverage. Public `saturation_at()` stays as the fully validated reference.
Every advance still refreshes live contact conditions and automatic ownership,
checks tree/World2D eligibility, performs absorption/drying in the original
order, and applies traction and signals at the original synchronous point.

The internal operation validates once before preparing or reusing contacts.
It reads all four current corner values using the passive drying clock, clamps
corners before interpolation through the same float32 Color representation,
and uses the same lerp order. It never caches saturation. Full and regional
geometry revisions invalidate handles before reused sample slots can be read.
Tree exit or lost contact clears the handle; it never retains geometry objects. Settings setters advance
revisions and invalidate cached validation, including direct shared Resource
edits, recomputing validation at mutation time rather than polling revisions on reads.
A surface validation cache is invalidated by assignments, settings signals, tree exit,
and geometry revisions; layer transforms and worlds are checked live. Custom backend
and grid overrides use public sampling. Queries that prepare geometry finish the
reference post-validation read sequence so callbacks can replace dependencies.
Geometry-affecting floor settings invalidate coverage independently of
drying changes, which do not reclip obstacles.

Differential tests require **exact equality**, with no numeric tolerance.
They cover same-tick deposits, overlap, drying and rewetting, seams, partial
polygons, boundary movement, transforms, full/regional replacement, slot reuse,
settings replacement/invalidity/recovery, marker deletion, reparenting, worlds,
automatic contact, signals, reentrant reads, and traction. Existing tests retain
direct-hit and obstacle contracts. Replay artifacts retain every tick's full
field-buffer SHA256, exact receiver states, ordered events, and synchronous
floor reads from change callbacks.

## Results and decision

Final CPU gate passed. Rendered, invalidation, replay, and sustained acceptance
remain in progress; see the final tables below once the run is complete.

Two experiments were rejected. Experiment A exaggerated moving-case gains with
unequal public/private sampling instrumentation, and uninstrumented moving gains
were only about 2%. Experiment B passed CPU and steady rendered gates but retained
patch objects until the next contact read, producing a repeatable 2–3 ms cold-read
spike after the first full rebuild. Both source states and raw reports are retained
under `experiment-a/` and `experiment-b/`; neither is acceptance evidence.

The final handle retains a patch instance identity and four sample indices,
not a patch object. The geometry can be destroyed during replacement; a weak-reference
lifetime test proves the handle cannot retain it. A focused 20-rebuild trial reduced
cold receiver passes to 0.419–0.543 ms with no second-pass spike. Full matched
acceptance is repeated for this final implementation.

Final production manifest SHA256 (sorted JSON of eight production files):
`2309c5136d08da7eb111c1d476f42333ff2cca156973414bac040b29a80d63a3`.
The preservation audit found no missing source files and no unexpected changes
to baseline files (AppleDouble archive metadata excluded).

The aggregate uses the union of timed scopes, not a sum of nested inclusive
timers: receiver advance, hose advance, surface physics, presentation process,
proxy synchronization, and public gameplay reads. It includes synchronous tint,
signals and traction inside those operations. It measures addon main-thread CPU
submission, not engine render-thread or OS compositor attribution. No addon
workers or waits were introduced. Separate uninstrumented OS child CPU totals
include all Godot threads plus setup/warmup and are labeled accordingly.

Behavior: final script check **85 scripts, 0 failed**; headless **90 cases,
5,410 checks, 0 failures**; rendered **3 cases, 14 checks, 0 failures**.
